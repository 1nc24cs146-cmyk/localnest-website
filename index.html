01 — HOW IT WORKS

Context before code, every single time

LocalNest follows the same order for every question and every task. The model is never handed your question on its own — it is handed your question plus the files that match it.

  1. 1

    Open a project and ask

    Pick a mode — Ask, Plan, Agent, or Build — and type your question or task in the sidebar panel.

    You can also select code and ask LocalNest to explain it, propose a diff-reviewed edit, or fix it from its diagnostics.

  2. 2

    It inspects your workspace first

    Before it answers, it searches your indexed project files and picks the ones that match your question.

    That context travels with the question to the model, so the answer is about your code — not generic code. In Fast mode it uses fewer files, so the first words arrive sooner.

  3. 3

    Ask answers, Plan plans, Agent proposes

    Ask never touches a file. Plan writes only a plan. Agent prepares complete files as one proposal card — and writes nothing yet.

    A plan lists the goal, the exact files to change, the risks, and how to check it worked. Happy with it? “Build this plan” moves it into Agent mode.

  4. 4

    You review every change

    Each proposed file has a preview. Open it beside the editor, read the full version, then approve files one by one, approve them all, or discard the proposal.

    Commands — installing packages, running tests — run only after you press “Run approved commands”. Dangerous commands are refused even if proposed.

  5. 5

    It verifies after you approve

    Once files are approved, LocalNest checks them, runs the checks, and shows the output in the panel.

    If something is still missing or broken, it proposes a fix through the same review and approval — repeating the verify-and-fix loop for up to 5 rounds.

  6. 6

    You can always undo

    The original contents of every file are recorded before approval. “Undo last approved changes” restores edited files and deletes newly created ones from that batch.

    Build mode works the same way for whole apps: describe a website or multi-file project, review the complete proposal, and only then let it be written.

02 — MODES

Four modes, one rule: no surprises

The mode decides what LocalNest is allowed to do with your answer — and, just as importantly, what it is not allowed to do.

AskQuestions, explanations

It does

Answers in the panel, grounded in the workspace files it found. Still searches your project even if no model is reachable.

It never

Changes a file. Ask is read-only by design.

PlanThink before building

It does

Writes only a plan: goal, exact files to change, risks, and how to verify the result.

It never

Changes a file. A plan becomes work only when you choose “Build this plan”.

AgentMulti-file changes

It does

Prepares a complete proposal — new and updated files in one card — then verifies the result after you approve.

It never

Writes anything before approval, or runs a command you have not approved.

BuildWhole apps

It does

Generates the complete files for a website, app, or larger multi-file project as one reviewable proposal. With no model reachable, it still creates a working app from a built-in template.

It never

Writes files without your approval.

04 — SETUP

Three steps, then chat

LocalNest does not install a model for you, and it does not download Ollama itself. It checks what is already on your machine and tells you plainly what is missing.

  1. 1Install Ollama

    Download Ollama for your system and run the installer. On Windows, restart Antigravity afterwards so the new terminal picks Ollama up. Choose “use Ollama locally” — no account is needed.

  2. 2Pull a model

    Start Ollama, then pull whichever model you want. A small model is the fastest way to get a first answer; a coding model is the better choice for larger changes.

  3. 3Open the panel and pick it

    Open LocalNest from the nest icon in the activity bar, or the Command Palette. The panel lists the models actually pulled on your machine — pick one and chat. Picking an installed model opens chat straight away.

Terminal — copy any command
$ ollama serveStarts Ollama on http://localhost:11434
$ ollama pull llama3.2:3bSmall and fast — a good first model (about 2 GB)
$ ollama pull qwen2.5-coder:7bCoding-focused — slower on CPU, stronger on code
$ ollama pull mistral:7bGeneral-purpose 7B — a balanced all-round choice
$ ollama pull phi3:miniVery small and fast — good on a weaker laptop
$ ollama pull codellama:7bCode-focused, from the Llama family
$ ollama pull llama3.1:8bLarger general model — strongest here, slowest on CPU
$ ollama listShows the models already downloaded on this machine

What LocalNest checks on first open

It reads the system: is the ollama program there, is its server running, and which models are pulled? The panel re-checks every time you open it.

  • !
    Ollama is not installed“Install Ollama to continue”, with a button to the download page. No chat is faked in the meantime.
  • …
    Installed, but not runningLocalNest tries to start an already-installed Ollama itself (auto-start is on by default). If that fails, it says to run ollama serve.
  • ○
    Running, but no model pulledIt stays on the model picker: pick a model, press Download, and chat opens when the download finishes.
  • ✓
    A model is already thereIt lists the models found and opens chat automatically — no setup step to get stuck on.

Honest expectations on a laptop

Ollama runs on CPU by default — no GPU setup is needed. The first answer after a download is the slowest, because the model has to load into memory. LocalNest keeps it loaded for 30 minutes, caps the context window, and uses all CPU threads, so later answers come sooner. On a laptop without a GPU, a 3B model will still take tens of seconds for a full answer. That is local CPU, not a failure — and Fast mode, with its smaller context, gets the first words out sooner.

05 — MODELS

Your model, your choice

There is no fixed model and no model list to subscribe to. The panel shows these 6 popular free models by default, plus any model you have already pulled — and if Ollama can pull it, LocalNest can use it.

llama3.2:3b

Start here for speed. Small, general-purpose, and the fastest route to a working chat on a laptop without a GPU.

About 2 GB to download. First answer is slowest; later answers speed up while the model stays loaded.

qwen2.5-coder:7b

Choose this for coding. A coding-focused model, better suited to larger edits, plans, and agent tasks.

Heavier on CPU than a 3B model — expect slower answers in exchange for stronger code.

mistral:7b

Balanced all-rounder. General-purpose 7B model, good for questions, writing, and everyday coding tasks.

Mid-weight on CPU — slower than 3B models, faster than 8B models.

phi3:mini

Smallest and fastest. A tiny model that runs comfortably on a weaker laptop, for quick questions.

Fastest answers here, but less capable on large, complex code changes.

codellama:7b

Code-focused, Llama family. Built for code generation and editing, a good alternative coding model.

Similar CPU cost to other 7B models.

llama3.1:8b

Larger general model. The strongest general model in the panel's default list, for harder questions.

Heaviest here — slowest on a laptop CPU, best reserved for a stronger machine.

Any Ollama model

Nothing is locked in. Type the exact model name in the panel, or pick it from the list of models pulled on your machine.

Switching models is just picking another one you have already pulled.

You can also point LocalNest at your own remote Ollama host instead of localhost, in Settings. Code then goes only to that host — still no cloud provider, no API key.
